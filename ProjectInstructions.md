-----Backend philosophy-----
Scripts includes holds all logic for the app.
The Script include structure is as follow : 
- A parent script for each table : Custom_Object. It holds a way to initialize or attach a glideRecord to a script, enabling record method extension via script include prototyping.
- Children scripts, one for each table that will hold logic. Extends Custom Object and define target table in TABLE_NAME property
- A global script (GlobalUtil) ==> holds logic that is not dependent on the app context (ex : duration helper)
- A helper script (WorkoutUtil) ==> holds logic that is dependent on the app context but not directly linked to one unique table functionality


-----App description-----
The workout app is an app for working out.
The objective is to be able to define exercices in a reusable way, and session that you can define, and session that you do (used for statistics as well).
Session can be defined with sets and repetition, or with categories and weight, each with various options (shuffle order, repeat the session, or infinite session)

An exercice is always composed of a preparation duration, effort duration and rest duration.
Categories should be hierarchical
